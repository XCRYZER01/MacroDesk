# Runtime profile bundle

`/macrodesk.bin` is generated by MacroDesk Studio and stored in the board's FAT
partition. It is intentionally separate from the exported `.macrodesk` JSON:
the runtime file contains two ready-to-draw RGB565 backgrounds and compact
button/page records, so the firmware needs no JSON or image decoder.

All integers are little-endian. The 16-byte header is:

| Offset | Type | Value |
|---:|---|---|
| 0 | 4 bytes | `MDB1` |
| 4 | `u16` | format version (`1`) |
| 6 | `u8` | profile count (`1..2`) |
| 7 | `u8` | reserved |
| 8 | `u32` | total file size |
| 12 | `u32` | CRC32 of bytes after the header |

Each profile contains its name and colours, 4-byte alignment, one 800 × 480
RGB565 image, touch zones with button records, then up to eight page records.
Strings use `u16 byte_length`, UTF-8 bytes and a terminating zero. The source of
truth for the exact reader/writer order is `macro_deck_runtime.cpp` and
`buildRuntimeBundle()` in `web/app.js`.

## Serial protocol

The Studio opens the CH343 `USB TO UART` port at 115200 baud and sends:

```text
MDUP <file-size> <whole-file-crc32>\n
```

Firmware replies `MDREADY`, receives exactly that many binary bytes into
`/macrodesk.tmp`, verifies both transport CRC and the bundle header/payload CRC,
then moves the previous file to `/macrodesk.bak`, promotes the temp file, removes
the backup and replies `MDOK` before restarting. A failed/interrupted transfer
keeps the previous bundle; boot also restores `.bak` if power was lost during
the short replace window.

The UART RX ring is set to 64 KiB before `Serial.begin(115200)`. The Studio
sends 512-byte chunks and waits for `MDPROGRESS` after every 4 KiB window. Keep
the buffer and acknowledged window in step; the Arduino default ring is too
small for sustained image uploads while FFat writes are in progress.

Diagnostic commands are `MDINFO` and `MDERASE`. Missing, corrupt, unsupported or
oversized bundles fall back to `macro_builtin_profiles`; the maximum accepted
runtime file size is 2 MiB.
